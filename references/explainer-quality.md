# 讲清楚与画面质量

当前用户优先精细二维图解、文字、图表和独立对象，不追求三维材质，不生成人物或环境场景

## 先设计信息变化

先用一句话写观众的问题与看完能复述的答案，再选一个贯穿例子。必要时采用故事→问题→机制→解决→回到原问题，流程解释则沿一份真实输入追踪输出，不强加虚构故事

每段在 explanation.json 记录：claim（讲什么）、before（原状态）、action（画面怎样变化）、after（结果）、meaning（说明什么）、object/outObject（追踪对象）、implementation（真实 HTML id）、handoff（承接关系）、focus（主要变化时段）、visibleSeconds（实际可读时间）

动作必须承担比较、因果传递、状态变化、证据展示之一。淡入、浮动、发光、粒子不能独自承担讲解。上一镜留下的对象要成为下一镜的输入，不能每镜清空后重新摆一组卡片

一次突出一个主要变化，可以保留已经理解的背景结构。标题、字幕、图内标签不同时争夺注意力，新增文字跟随相关动作出现，结论至少留出一次稳定阅读

## 精细二维的统一规则

- 每片固定配色、字体、栅格、线宽、图标语法、运动曲线与转场规则，内容变而系统不变
- 1920×1080 桌面观看，正文可从40–48px试排，图内标签通常28–32px；必须按最终缩放后的实际字号检查，不能只看源码数字
- 核心信息不能随着对象缩小变成微缩字，退出焦点后删除重复标签或用独立固定字号标签承接
- 对比靠位置、面积、长度、颜色和连接关系表达，避免满屏大字、随机运动和空转装饰
- 需要多信息时逐步积累关系图或对比图，不在同一时刻塞入全部说明
- 素材、字体、音轨本地化，真实来源与许可登记；不得自动继承参考片音乐

## 三层验收分别报告

1. 结构检查：explanation_check.py 验证字段、阅读预算、时序、承接和代码锚点；这是声明一致性，不能证明动画真的表达了声明
2. 画面检查：HyperFrames check + 连续样片 + 转场前后截图，检查运行、遮挡、对比度、实际字号和动作；警告逐项处理，不能用总分掩盖问题
3. 理解检查：审查者按每镜写“看到了什么变化、因此明白什么”，再遮住字幕检查机制是否仍有画面依据；请目标观众复述主结论与步骤。没做真实观众测试就标未验证

检查技术通过不能冒充审美、事实或理解通过。样片先过用户认可，再扩展整片；增加信息应先增加关系与证据，不能靠缩字与加速
