# 故事动效工坊 · story-motion-studio

**把你的主题做成可修改的网页动画，再导出为 MP4**

适合科普讲解、工作流程、数据与独立结构展示、文字图形动效。制作以同一问题或例子贯穿，避免只做图片轮播

你负责说明内容目标、提供参考并确认效果；Codex 读取技能、写讲稿和动画代码，调用浏览器及 FFmpeg 完成导出


## Windows 安装

仓库地址：`https://github.com/yangmuye520-dotcom/story-motion-studio`

下面的远程命令在仓库发布后可用。运行者应先查看本仓库安装脚本，再在PowerShell执行：

```powershell
$setup = Join-Path $env:TEMP ("story-motion-" + [guid]::NewGuid().ToString("N") + ".ps1"); Invoke-WebRequest "https://raw.githubusercontent.com/yangmuye520-dotcom/story-motion-studio/main/install.ps1" -OutFile $setup; & $setup -InstallSystemTools
```

若脚本执行策略拦截，在已确认下载文件内容后，可用 `powershell -ExecutionPolicy Bypass -File <下载的脚本路径> -InstallSystemTools` 运行本次安装，不修改全局执行策略

已经下载或克隆仓库时，在仓库目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -InstallSystemTools
```

安装行为：

- 按 `upstreams.lock.json` 的固定提交下载七个来源，核对18个必需来源文件
- 下载 lemo 实际资料库，跳过上游大型媒体演示，保留代码和文档
- 创建独立 Python 虚拟环境，安装基础依赖；优先使用现有 Chrome，缺少时下载 Chromium
- 使用 imageio-ffmpeg 提供的 FFmpeg，不要求手工配置系统 PATH
- 写入本机路径配置，运行来源检查与真实浏览器绘图小检查
- 遇到已有技能目录或本机配置即停止，不覆盖，不执行自动升级

`-InstallSystemTools` 允许在缺少 Git/Python 时调用Windows自带的winget安装，可能出现系统安装提示；没有winget时需先手工安装Git和Python 3.10以上

只检查安装计划：`python install.py --check`，不联网、不写文件。高级路径选项见 `python install.py --help`，`--skip-runtime` 只装来源，不代表完整安装成功

安装范围是无配音代码动画路线，不下载语音克隆模型、不配置付费API。工具安装仍依赖网络，软件版本范围见 `requirements-install.txt`，上游固定版本见锁文件

## 第一次使用

在 Codex 中发送下面这段话，把方括号替换成你的要求：

```text
用 story-motion-studio 做一条视频
主题：[要讲什么]
观众：[谁来看]
看完能：[理解或完成什么]
时长与画幅：[例如90秒、16:9横屏]
风格：[黑金讲解 / 三维结构 / 情境粒子，或提供参考]
资料：[我提供材料，或请先核实来源]
声音：[无配音或中文旁白，字幕要求，BGM来源]
限制：[例如不生成人物和环境场景，只使用免费工具]
先给讲稿、分镜和10秒连续样片，我确认后再制作整条
交付MP4、完整HTML工程、文稿分镜和资料来源
说明七个上游技能各自的实际贡献
```

已有喜欢的样例时，直接说“沿用这条样例的字体、配色和运动规则，内容改为……”

普通用户无需手工运行全部制作命令，先让 Codex [检查制作环境](docs/setup.md)，缺少什么再补什么

## 先看已有风格

打开[样例库](examples/index.html)观看短片，或打开[原片与样片对照](examples/compare.html)

| 调用名 | 适合讲什么 | 主要表现 |
|---|---|---|
| 黑金讲解 | 概率、比较、数据与机制 | 实体物件、组合推演、图表接续 |
| 三维结构 | 系统、通道、局部与整体 | 独立结构、信号跟随、尺度切换 |
| 情境粒子 | 问题、关系与解决过程 | 追踪同一批点，状态变化后回到原问题 |

三套24秒样片已获原用户认可，可作为风格起点；样片画内可能保留制作时的候选标记，当前状态以样例清单和认可记录为准

选择风格不等于复制旧片内容或自动沿用旧音乐。当前个人约定只生成独立对象和结构，不新造人物与环境场景

## 制作会经历什么

1. **整理要求与资料**：明确一件要讲清的事，核实关键事实
2. **讲稿与分镜**：写清每段新增的信息，以及对象怎样变化
3. **连续样片**：检查文字、动作、风格和音乐是否符合预期
4. **完整工程**：编写网页、时间轴与动画代码，浏览器绘制连续画面
5. **视频导出与审片**：逐帧取图，FFmpeg编码并合入音轨，修正后交付

只想要讲稿、分析或 HTML 时，直接说明，流程会停在你指定的阶段

## 你最终拿到什么

| 交付 | 用途 |
|---|---|
| `final.mp4` | 播放、展示与分享 |
| 完整 HTML 工程 | 修改文字、颜色和动作，再次导出 |
| 文稿、分镜、来源与素材说明 | 了解内容依据，继续修改 |
| 采用记录与检查报告 | 追溯七个来源实际做了什么，检查覆盖到哪里 |

**HTML 工程需要整目录保存，修改后旧 MP4 不会自动更新**。具体打开方式与改稿方法见[运行和修改工程](docs/editing.md)

## 七个 skills 怎样一起用

`story-motion-studio` 组织一条制作流程，七个上游提供具体方法、代码或工具，共同影响同一份工程

| 来源 | 本流程采用的职责 |
|---|---|
| `wtt-code-animation-studio` | 文稿与动作时长、时间轴、素材版本 |
| `lemo-opuscar` | 故事目标、转折、结尾回扣 |
| `huashu-art-motion` | 对象前态、动作、后态与镜头表检查 |
| `video-shotcraft` | 镜头目的、运动与独立审片 |
| `dashi-animationstyle` | 字阶、语义色、阅读预算与一致性 |
| `mg-styles-15` | 从真实示例适配动效实现 |
| `xilo-opus-video` | 确定性绘制、取帧与导出检查 |

七个来源都是当前制作流程的必需依赖，不能只复制总技能就宣称已具备完整制作环境。它们不是七个视频模型，也不是七段成片简单拼接

## 使用前要知道的边界

- **代码动画**：擅长解释图形、文字和结构；逼真实拍、人物舞蹈或动物运动需要对应素材或模型
- **声音**：按项目准备音乐或旁白，本包不自带可保证演员级效果的通用配音能力
- **费用**：本地工具可使用免费方案，AI账户、外部模型与素材可能另有费用，涉及收费先说明
- **质量**：七项参与和技术检查通过，不代表审美或听感自动合格，仍要观看、试听和反馈
- **迁移**：播放 MP4 无需制作依赖；播放 HTML 需完整工程与本地服务；重新制作需七个来源和运行环境
- **素材**：内置原片和原音轨用于本地参考，公开分享前单独核对授权
